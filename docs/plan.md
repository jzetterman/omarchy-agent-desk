## A. Architecture overview

Four process kinds, one writer per file class. The shell never touches provider files; the runner is the only writer of plugin state and records; credential files are read by collectors and, only through named `credfile` entry points (`credential_hash` at decision time, `replace_current_entry`, the startup temp recovery of E.3), by the runner, which never logs or emits their contents (the A8 scan covers the runner process too); the shim reads state and nothing else.

```

 ┌───────────────────────────────┐               state.json  (0600, atomic)             records/<provider>/<id>.json (0600)
 │ Panel.qml  (bar icon + panel) │               homes/<provider>/<uuid>/ (0700)        runner.log (0600, no tokens)
```

Data flow: settings → QML validates (R27) → `settings` command → runner. Runner → `snapshot` event after every change (state, records, providers, routing, login progress, first provider). QML renders snapshots only; it holds no derived truth except formatting and the 30 s countdown re-stamp (R21). Records persist on disk so a restarted runner serves last-known values with age (R6).

## C. Contracts (versioned; bump `schemaVersion` on any breaking change)

### C.1 `descriptor.json` (R2) — schemaVersion 1
```jsonc
{ "schemaVersion": 1, "id": "claude", "name": "Claude Code",
  "mark": "mark.svg", "markLight": "mark-light.svg", "glyph": "󱚣",
  "binary": "claude", "homeEnv": "CLAUDE_CONFIG_DIR", "defaultHome": "~/.claude",
  "commands": { "login": ["claude","auth","login"], "logout": ["claude","auth","logout"] | null, "launch": ["claude"] },
  "credential": { "file": ".credentials.json", "currentEntry": "claudeAiOauth", "lockFile": null | { "name": "auth.json.lock", "kind": "pidfile" },   // the CLI's own lock, if any; only "pidfile" exists in v1 (Grok)
                  "tempFiles": { "refresh": ".credentials.json.agent-desk-refresh", "transaction": ".credentials.json.agent-desk-txn" } },
  "sharedEntries": ["CLAUDE.md", "settings.json", ...],                       // R8, linked into isolated homes
  "accountState": [ { "name": ".claude.json", "defaultPath": "~/.claude.json", "stripKeys": ["oauthAccount","userID", ...] } ],
  "scale": "sniff" | "points" | "fraction" | "cli",                          // D7
  "installDirs": ["~/.local/share/mise/shims", "~/.local/bin"],               // E.6 fallback only; never a recorded path
  "installHint": "Install Claude Code: mise use -g claude@latest",             // string, optional: the not-installed hint the panel shows (D.*); absent → "Install <name>"
  "urls": { "usage": "https://…", "identity": "https://…" | null, "refresh": "https://…" | null,
            "refreshFormat": "json" | "form",                                  // request body encoding for the grant
            "clientId": "…" | null,                                            // constant public client id (Claude)
            "clientIdKey": "oidc_client_id" | null } }                         // R2 v12.1: key inside the current credential entry that holds the CLI's own public client id (Grok)
```
Loader rules: `id` matches `^[a-z0-9-]+$`; `homeEnv` matches `^[A-Z_][A-Z0-9_]*$` (it is interpolated into the E.6 probe); every non-null URL field is `https://` or the descriptor is rejected (D8; `usage`/`identity` may be null for CLI-transport providers such as Codex); `urls.refresh` set requires `refreshFormat` and exactly one of `clientId` / `clientIdKey`, else the descriptor is rejected; `credential.lockFile.kind`, when present, must be `"pidfile"` (any other value rejects the descriptor); `binary` matches `^[A-Za-z0-9._+-]+$` and every `commands.*[0]` equals it; a provider directory without a valid descriptor is reported in the snapshot as `providerErrors: [{dir, message}]` (C.4) and skipped. Isolated path of an account-state entry is `<home>/<name>`; its default-home path is `<home>/<name>` when the imported account's `homeFromEnv` is true (the CLI was pointed at that home by its env var), else `defaultPath` expanded (Claude: `$CLAUDE_CONFIG_DIR/.claude.json` when the variable is set, else `~/.claude.json`; acrogenesis `ai_accounts.sh:163-169`).

### C.2 Collector CLI (R2, R6, R34)
`python3 providers/<id>/collector.py --mode full|identity --home <path> --home-kind default|isolated [--home-env-set] --binary <path-or-empty> [--deadline <epoch-s>]`
`--home-env-set` is passed for the imported account when `homeFromEnv` is true (C.3) and for every isolated home; it tells a collector whose identity file moves with the env var (Claude's `.claude.json`) which path to read.
Env read: the two test hooks `AGENT_DESK_NOW` (epoch seconds, test clock; otherwise wall clock) and `AGENT_DESK_CA_FILE` (a CA path the collector reads and passes to `http.py` as its `cafile` parameter, E.8; `http.py` itself reads no environment) are honored only when the collector is started with the argv flag `--test`, which only a runner itself started with `serve --test` passes; without `--test` the runner strips every `AGENT_DESK_*` variable from the inherited environment before spawning, so an ambient value can never reach a collector (R29). No other env is read; the home env var is not consulted (the runner passes `--home`). A collector that must run the CLI (Codex app-server) sets the home env var on that child only. Exit 0 with one JSON record on stdout; exit 2 for a usage error (runner maps to `failed`). Never prints credential values. `identity` mode opens no socket and never refreshes. **Usable identity** (R10, D3) = identity-mode `status ≠ not-signed-in` (credential file present and an R4 entry selected) **and** a non-empty normalized email; an identity file written before the credential file (Claude writes `.claude.json` first) is therefore not yet usable, and the next poll picks it up. In the default home (`--home-kind default`) an expired token returns `expired`/`default-home` with no socket opened — the usage request is never sent, so no 401 can be mapped to `rejected` (R5, §4). `record.normalize` sorts `windows` by the R21 kind order then label (QML never sorts), emits only the fields listed above (allowlist), and drops any key whose name matches `token|key|authorization|secret` case-insensitively at any depth (R28). `runner.log` lines carry only the HTTP status code, a short URL id (`claude.usage`, `grok.refresh`; never the URL or a body), the exception class, and status words; A8 scans `runner.log` too. Hard timeout is the runner's (30 s, own session); `--deadline` lets the collector budget network timeouts and D1 step 5.

Record (stdout and cache file are the same shape):
```jsonc
{ "schemaVersion": 1, "provider": "claude", "mode": "full",
  "status": "ok|not-installed|not-signed-in|expired|rate-limited|offline|failed|no-limits",
  "statusReason": null | "default-home|deferred|grant-rejected|rejected|unsupported-refresh",   // only with expired
  "help": "one human line", "identity": { "email": "", "org": "", "plan": "" } | null,
  "windows": [ { "id": "session", "kind": "session|weekly|monthly|billing-period|model-scoped|<other>", "label": "Session",
                 "used": 0.05, "resetsAt": "ISO-8601", "periodStart": "ISO"|null, "note": ""|null } ],
  "balance": { "remaining": 6, "funded": 10|null, "spent": 4|null, "unit": "credits", "precision": 0, "used": 0.4 } | null,
  "collectedAt": "ISO",                                   // set by the collector
  "fetchedAt": "ISO"|null, "accountId": "…", "generation": 3, "installed": true   // set by the runner
}
```
Runner merge rule (one place, `runner.py::merge_record`): for `ok`/`no-limits`/`not-signed-in`/`not-installed` the new record replaces the cache and `fetchedAt = collectedAt`; for `expired`/`rate-limited`/`offline`/`failed` the cache keeps its `identity`, `windows`, `balance`, `fetchedAt` and takes the new `status`, `statusReason`, `help`, `collectedAt` (last-known values with age, R6). Stale = `now − fetchedAt > refreshIntervalSec`, computed in QML at each 30 s re-stamp (R25). `balance.used` per spec §4 in `record.py::balance_used` (never NaN). Window `id` = collector-supplied, else `kind + ":" + label.lower()`.

### C.3 `state.json` (R8, R12, R13) — schemaVersion 1
```jsonc
{ "schemaVersion": 1, "generation": 12,                 // publish counter: +1 on every atomic publish, for readers (A6d); unrelated to per-account collector generations
  "accounts": [ { "id": "<uuid4 hex, 32 chars>", "provider": "claude", "kind": "imported|isolated", "name": "john@example.com",
                  "home": "/home/john/.claude", "homeFromEnv": false, "createdAt": "ISO", "generation": 3 } ],   // homeFromEnv: imported accounts only; true when the E.6 probe reported the home env var set at import
  "active": { "claude": "<id>" },
  "routing": { "installed": false, "partial": false, "shims": ["claude"], "shadowed": { "grok": "/home/john/.grok/bin" }, "rcFile": "/home/john/.zshrc", "rcCreated": false } }   // rcCreated: install created the rc file (E.7)
```
Validation: unknown top-level keys ignored; only structural faults invalidate the file (not JSON, not an object, bad `schemaVersion`, `accounts` not a list, an account with a bad id or unknown kind); an account whose provider has no valid descriptor is retained verbatim, never collected, never deleted by cleanup (its tree counts as saved), and surfaced in `providerErrors`; `home` must be an absolute path with no `.` or `..` component (checked by splitting on `/`) for `kind: imported` and must be `null` for `kind: isolated`, anything else invalidates the file (recovery error, R7a); `active[p]` must name a saved account of `p` else it is reset to the imported account. Publish: write `state.json.tmp` (0600), fsync, rename (R12, A6d). For `kind: isolated` the `home` field is `null` and every path (collector `--home`, launch, relink, replace, purge, `rmtree`) is derived through `paths.isolated_home(provider, id)` (E.4), never read from state; only imported accounts carry a `home` string. Card order = imported first, then isolated by `createdAt` (§4). `generation` per account is advanced by replacement and removal; every collector run carries it (D2).

### C.4 Runner protocol (stdin → runner, stdout → QML), one JSON object per line
Wire envelope, stated once: every stdin line is `{"cmd": <name>, ...}`; every stdout line is `{"event": <name>, ...}`; unknown `cmd` → `caption`, unknown `event` → ignored by QML.
Commands: `settings{refreshIntervalSec,providerOrder,providerEnabled,warningThreshold,criticalThreshold,readoutScope}` (the runner computes the readout, so it needs the thresholds and scope; `readout` on/off stays QML-only), `refresh{accountId|"all", manual:true}` (every refresh from QML, IPC, panel open, or the past-reset queue is `manual:true`: it ignores backoff and obeys only the 60 s floor; the runner-internal `force` of E.1 is never accepted on stdin: a `force` field arriving on stdin is ignored and the request is treated as manual; every F/Keys.State send sets `manual:true` explicitly), `set-active{accountId}`, `next`, `add-account{provider}`, `cancel-login`, `login-decision{action:"replace"|"discard"|"abort"}`, `sign-in-again{accountId}`, `rename{accountId,name}`, `remove{accountId}`, `relink{accountId}`, `launch{accountId}`, `routing-install`, `routing-remove`, `snapshot`.
Events: `snapshot{state (each account also carries a derived `homePath`: `paths.isolated_home` for isolated, the recorded `home` for imported; kit props get it through `Format.plain`, our own `Text{textFormat: PlainText}` in DetailView renders it unmangled, R24), records{accountId→record (+ sharedHealth for isolated accounts, E.4; + sameAccountAs: {id, name}|null computed by the runner from identity match, R11/A12b)}, providers[{id,name,markPath,markLightPath,glyph,installed,installHint,enabled,binaryPath}], firstProviderId (E.1), readout{used: number|null, level: "none"|"normal"|"warning"|"critical", top: null | {provider, providerName, accountId, accountName, kind: "window"|"balance", label, used, resetsAt|null, remaining|null, unit|null, precision|null, fetchedAt}} (empty scope = `{used:null, level:"none", top:null}`; ties on `used` resolve by provider order, then card order, then kind order, R17), pathProbe:"pending"|"ok"|"fallback" (while not "ok", a provider without a saved account is `installed:false` with the hint of E.1), login{provider, phase: "pending-pid"|"waiting"|"decision-replace"|"decision-imported"|"decision-other"|"committing"|"failed", stagingId, matchedAccountId, message}|null (while non-null, `add-account` and `sign-in-again` are refused with a caption; `cancel-login` in `pending-pid`, `waiting`, or any decision phase discards the staging tree without committing and is ignored during `committing`; a login survives panel close (spec v12.5): `login` stays non-null and the panel re-renders the in-progress or decision card from it on reopen; a success — unique identity on Add, or same identity on Sign in again — is published in the same snapshot that sets `login` to null, E.3), providerErrors: [{dir, message}], error|null, generation}` after every change, including a `settings` command (which recomputes `readout` and `firstProviderId`), and `caption{text}` for transient notices (R11 logout failure, R12 announcement). `remove` runs its logout as a worker job (E.5) and the snapshot that publishes the removal arrives when the job returns; other commands keep flowing meanwhile. Every command that fails answers with `caption` and leaves state unchanged. Service.qml sends `settings` as the first command after every Process start (R27, R16), so the runner never computes a readout on defaults. IPC verbs `show`/`hide` are aliases of `open`/`close`, kept for parity with the kit's built-in handler. The runner exits on stdin EOF; `snapshot.error = "runner-stopped"` is set by Service.qml, not the runner (E.1a).

### C.5 Cache and data layout (R28, §9.1)
One path rule, shared by `paths.py` and the shim: `$HOME/.config/omarchy/agent-desk/` and `$HOME/.local/state/omarchy/agent-desk/`, literal as spec §9.1 pins them; `XDG_CONFIG_HOME`/`XDG_STATE_HOME` are deliberately ignored so the runner (launched by the shell) and a terminal shim can never disagree (`test_routing.py` runs the shim with `XDG_CONFIG_HOME` set to a decoy and asserts it reads the pinned file).
`~/.config/omarchy/agent-desk/` 0700: `state.json`, `homes/<provider>/<uuid>/` 0700, quarantine `homes/<provider>/<uuid>.quarantined-<UTC yyyymmddThhmmssZ>/` (timestamp from `Clock`, as is the `.diverged.<UTC>` suffix of E.4). `~/.local/state/omarchy/agent-desk/` 0700: `records/<provider>/<uuid>.json` 0600 (removed with the account, R11), `runner.log` 0600 (truncated at runner start when above 1 MB). `~/.config/omarchy/agent-desk/runner.lock` 0600: flock held by the live runner for its whole life (E.1a). Per-home lock: `<isolated home>/.agent-desk.lock` (flock, 0600) — isolated homes only; the imported default home never gets a lock or any other Agent Desk file (A4): reads there are `O_NOFOLLOW` and create nothing, and no transaction ever targets it (E.5 aborts on an imported match). Login pid file: `<staging>/.agent-desk-login.json` `{pid, starttime}` (unlinked by the handler that publishes the new account, and gone with the tree on discard). No process ids are persisted anywhere else (R6).

### C.6 Settings (R27) — read in QML with `setting(name, fallback)`, validated by `Panel.qml::validatedSettings()`; every key except `readout` is forwarded to the runner in the `settings` command (C.4)
| key | default | validation |
|---|---|---|
| `refreshIntervalSec` | 900 | `Number()`, non-finite → 900, `< 60` → 60 |
| `warningThreshold` / `criticalThreshold` | 0.75 / 0.90 | wrong type or non-finite → default, then clamp 0..1; warning > critical → warning = critical |
| `readout` | true | non-boolean → true |
| `readoutScope` | `"active"` | not in {active, all} → `"active"` |
| `providerOrder` | `["claude","codex","grok"]` | non-array → default; non-string/unknown ids dropped; duplicates keep first; unlisted appended in id order |
| `providerEnabled` | `{}` (= all enabled) | non-object → `{}`; non-boolean values dropped |
CLI: `omarchy bar set io.github.jzetterman.agent-desk refreshIntervalSec 600 --json`; nested values whole: `omarchy bar set io.github.jzetterman.agent-desk providerEnabled '{"grok":false}' --json` (API doc §1.8: the shell ignores manifest defaults, so all defaults live in `Panel.qml`).

## D. Provider designs (contracts from teardown §5; endpoints are descriptor constants)

### D.claude (Claude Code)
- Home env `CLAUDE_CONFIG_DIR`, default `~/.claude`. Binary `claude`. Login `claude auth login`, logout `claude auth logout`, launch `claude` (verified `claude auth --help`).
- Credential `.credentials.json`, current entry key `claudeAiOauth` `{accessToken, refreshToken, expiresAt(ms), subscriptionType, rateLimitTier}` (teardown §5.1). API-key-only files (no `claudeAiOauth.accessToken`) are `not-signed-in` (§4). No CLI lock file.
- Usage: `GET https://api.anthropic.com/api/oauth/usage`, headers `Authorization: Bearer <accessToken>`, `anthropic-beta: oauth-2025-04-20`, `Accept: application/json`. Fields: `five_hour{utilization,resets_at}` → kind `session`, label "Session"; `seven_day_oauth_apps` else `seven_day` → `weekly`, "Weekly"; `limits[]{kind,percent,resets_at,scope.model{id,display_name}}` → `model-scoped`, label `"<display_name> · <window word from kind>"`, id `model:<model.id>:<kind>`; `extra_usage{is_enabled,monthly_limit,used_credits}` (cents) when enabled → `monthly` window "Extra usage", `used = used_credits/monthly_limit`. Scale `sniff`: any utilization/percent > 1 in the whole payload → points; clamp after (D7). ## E. Mechanism design (refines D1–D8)

### E.1 Runner scheduling (R6, D2)
`Scheduler` owns per-account entries `{nextDueMono, lastStartMono, backoffMultiplier (1,2,4,8), inflight, held, generation}` (`held`: set by two owners — a login in `decision-replace`/`committing` against that account, cleared on any login exit, and a Removal job (E.5) for the life of that job, cleared when it returns; while set, neither scheduled nor manual runs touch the account and its backoff is unchanged — otherwise our own isolated refresh could rewrite the target during a decision or a removal) and one `Clock` (`now()`, `monotonic()`, `sleep(s)`; `FakeClock` in tests — **every time read in `runner.py`, `credfile.py`, and collectors goes through `Clock`; the floor (60 s), interval, `collectorTimeoutSec` (default 30, used for collector runs, logout jobs, and identity polls), `probeTimeoutSec` (default 5, the PATH probe), and grace (2 s) are constructor arguments**). `FakeClock.sleep(s)` advances `now` and `monotonic` by `s` and returns at once; any advance writes one byte to the wake-up pipe so a loop blocked in `select` re-evaluates due times; unit tests that drive the Scheduler without a loop call `Scheduler.tick()`, which runs one pass of due work without `select`. Loop: `select` on stdin and a wake-up `os.pipe` (workers append results to a `collections.deque` and write one byte; `queue.Queue` is not selectable) with timeout = next due; on due, spawn `subprocess.Popen(argv, start_new_session=True, env=minimal_env, stdout=PIPE, stderr=DEVNULL)` in a worker thread that `wait(timeout=collectorTimeoutSec)`s, then `os.killpg(SIGTERM)`, waits 2 s, `os.killpg(SIGKILL)` → result `failed` with help "Collector timed out". `minimal_env` = `PATH` (interactive PATH from E.6), `HOME`, `LANG`, and, only when the runner was started with `serve --test`, `AGENT_DESK_NOW` and `AGENT_DESK_CA_FILE` plus the `--test` argv flag on the collector; otherwise every `AGENT_DESK_*` variable is stripped; nothing else (so fakes take their script from `$HOME/.fake-cli.json`, G); never the home env var, never tokens (R28). `minimal_env` is for collector and logout children only; terminal launchers inherit the runner's own environment (E.3). Remove/logout (E.5), identity polls (E.3), `discard_staging` (E.3; its result publishes the snapshot), and the PATH probe (E.6) are worker jobs on the same pool, so a 30 s logout never stalls `set-active` or snapshots. Single-flight: a due account with `inflight` is skipped. Manual (`refresh`, panel open, past-reset queue, IPC, right click): skip an account when `monotonic − lastStartMono < 60`; ignore backoff. Force (runner-internal only, never accepted on stdin): used by exactly three callers — after a committed Replace / Sign in again (E.5), for a newly saved added account (E.3), and for the account import-on-install saves (this section) — it sets `nextDueMono = now`, ignores the floor and backoff, and resets the multiplier, so the card never sits on skeleton rails until the next tick (R10, R14). Under `--test` every collector spawn sets `AGENT_DESK_NOW = Clock.now()` and derives `--deadline` from that same value, so runner, collector, and E.2 step 9 share one clock in tests (R34). A `settings` command with a changed interval sets every entry's `nextDueMono = lastStartMono + newInterval × multiplier` (due now if already past) and emits a snapshot (R27). Scheduled: due at `lastStart + interval × multiplier`; backoff iff `status ∈ {rate-limited, offline, failed}` or (`status == expired` and `statusReason == grant-rejected`): multiplier = min(8, max(2, 2×previous)); every other outcome (`ok`, `no-limits`, `not-signed-in`, `not-installed`, and `expired` with `default-home`, `deferred`, `rejected`, or `unsupported-refresh`) resets it to 1. This matches A3: refresh failures surface as those statuses, a local abort is `deferred`. Result handling (collector jobs only; login identity polls are a distinct job type that emits `login.phase` and never reaches `merge_record`, E.3): drop if the account id is no longer in state (removed meanwhile) or `result.generation != account.generation` (D2, A6d); else merge (C.2), write record atomically, and for an isolated account with a successful record compute `shared.health` (E.4) into `records[id].sharedHealth`; emit snapshot. `runner.log` is truncated at start when above 1 MB. `firstProviderId` = the first provider in `providerOrder` (C.6) that is enabled and installed (E.6 rule), else `null`: then `next` and the header action are no-ops and the header action is hidden (R18); `next` wraps that provider's card order (§4); a provider with `providerEnabled: false` is skipped by the scheduler, the readout, the tooltip, and `next` (R20). At startup, before the first snapshot, every `records/<provider>/<id>.json` belonging to a saved account is loaded into the cache if it parses as a C.2 record (so a restarted runner serves last-known values with their age, R6/R25); unparsable files and files for unsaved ids are unlinked. Install detection runs at start and each cycle against the cached interactive PATH of E.6 (the probe itself runs only at startup and on manual refresh); a provider that becomes installed imports its default home once (R8) with a stable uuid, `home = os.path.abspath(os.path.expanduser(env var value or defaultHome))` — a value that is not a plain absolute path afterwards (contains `.`/`..` components, or is empty) skips the import and is reported in `providerErrors` — and `homeFromEnv` (C.3), the env var value coming from the E.6 probe of the interactive environment; **no import happens while `pathProbe` is `"pending"` or `"fallback"`**, and while it is not `"ok"` a provider with no saved account is reported `installed: false` with `installHint` "Checking PATH…" (pending) or "PATH probe timed out · refresh to retry" (fallback), so the panel never shows an installed-but-unimported section with a live "+ Add account"; providers that already have saved accounts keep collecting on the cached PATH; a returning probe result wakes the loop (the wake-up pipe) and runs one install-detection + import pass immediately, followed by a snapshot, so a fresh install never sits idle with nothing due.

### E.1a Runner lifecycle (what makes the single-writer table in A true)
The runner exits on stdin EOF (the shell died or reloaded the plugin). At start it takes `flock(LOCK_EX|LOCK_NB)` on `~/.config/omarchy/agent-desk/runner.lock` and, if held, writes one line to stderr (`agent-desk-runner: another runner holds runner.lock`) and exits 75 without touching any file. On stdin EOF the main loop `killpg`s every worker child and exits without waiting for results. Service.qml restarts an exited runner with a backoff of 1 s doubling to 30 s, except exit 75, which is retried at a fixed 1 s and not counted (after 10 such retries Service.qml sets `snapshot.error = "runner-locked"`, panel: "Another runner holds runner.lock", and keeps retrying every 1 s); after 5 counted exits within 60 s it stops restarting, sets `snapshot.error = "runner-stopped"` (panel: "Runner stopped · see runner.log"), and a manual refresh (`r`, right click, IPC) resets the counter and sets `Process.running = true` again (the Process is dead by then; `running = true` restarts it). Per-home locks never protect `state.json`; this lock and policy do.

### E.2 Isolated-home token refresh (R5, D1) — `credfile.refresh_transaction(home, descriptor, clock, deadline, http, select, expires_at, merge)`
`credfile.py` stays provider-agnostic (R2): it owns locks, hashes, temp files, write, fsync, and rename only. The three callbacks come from the calling collector: `select(doc) -> (key, entry)` (R4 entry selection: Claude returns `doc["claudeAiOauth"]`; Grok filters `auth_mode`/`sk-`/`xai-` and takes the first remaining), `expires_at(entry) -> epoch seconds` (Claude `expiresAt` ms, Grok `expires_at` ISO), and `merge(doc, key, response, now) -> doc` (Claude maps `access_token→accessToken`, `refresh_token→refreshToken`, `expires_in→expiresAt` ms; Grok maps to `key`, `refresh_token`, `expires_at` ISO). No provider `if` exists in `credfile.py`.
1. Read credential file (0600 fd, `O_NOFOLLOW`), `select` the current entry (R4). `expires_at(entry) > now` → skip. Expired < 10 min → `expired/deferred`.
2. `flock(LOCK_EX|LOCK_NB)` on `<home>/.agent-desk.lock`, retried every 100 ms via `Clock.sleep` for at most 1 s (`fcntl.flock` has no timeout), else `deferred`. Then the descriptor's `lockFile`: kind `pidfile` → read it; content names a pid that is alive in `/proc` → `deferred` (the CLI is mid-write); absent, unparsable, or dead pid → proceed under our own lock without touching the CLI's file (we never take it over). Hold until step 10. The step-6 hash check, not the CLI's lock, is the real guard against a concurrent CLI write.
3. If `<tempFiles.refresh>` exists (D1 as amended): parse it and read its sidecar `<temp>.base`; complete credential file **and** `sha256(credential file now) == base` → `os.replace` over the credential file (commit of a prior answered refresh issued against exactly this file); otherwise (incomplete, no sidecar, or the CLI rewrote the file since) unlink temp and sidecar. Return `expired/deferred` either way.
4. `os.open(temp, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW, 0o600)`, then write the step-1 sha256 to `<temp>.base` (0600, holds only a hash, never a token); failure → `deferred`.
5. `deadline − clock.now() < 2` → `deferred` (temp removed).
6. sha256 of the bytes read in step 1 vs a re-read now under the lock; differ → `deferred`.
7. Client id = `urls.clientId`, or the current entry's `urls.clientIdKey` value (R2 v12.1; missing → `expired`/`unsupported-refresh`, temp removed, no request). `http.post(descriptor.urls.refresh, body, headers, timeout = min(cap, deadline − now))` where `cap` is an `http.post` parameter (default 10 s; collectors pass it, tests scale it with `collectorTimeoutSec`; the response matrix itself runs in-process with an injected `http`, G) where `body` is `json.dumps` for `refreshFormat: json` and `urllib.parse.urlencode` for `form` (a refresh token containing `&` or `=` stays one field; Phase 5 tests it).
8. 401/403 or body `error == "invalid_grant"` → `expired/grant-rejected`; connection/DNS error → `offline`; 429 → `rate-limited`; timeout/5xx/3xx/malformed → `failed`. Temp removed, file untouched.
9. Success: re-read the credential file under the lock, `merge` the provider's answer into the current entry of *that* document (every other entry and field preserved), `write` + `fsync` the temp; `os.replace(temp, credential)`. If the current entry's token changed between step 6 and this re-read (a CLI refreshed concurrently), the provider's answer is still committed: the provider has already rotated the grant, so dropping it would strand the home (R5: a token obtained is never dropped; README residual). Failure after the response → leave the fsynced temp (recovery for step 3), return `failed` (backoff).
10. Release locks; `finally` unlinks the temp and its `.base` sidecar this run created unless step 9 kept them.
Return value drives the collector's usage request: after a successful refresh it re-reads the file and proceeds to fetch usage in the same run (one refresh per run); **any non-success (`deferred`, `grant-rejected`, `unsupported-refresh`, `offline`, `rate-limited`, `failed`) is the collector's final status for that run — no usage or identity socket is opened**, otherwise a deferred token would 401 into `expired`/`rejected` and offer Sign in again (D1, A3). Clock injection points: steps 1, 5, 9 (`expiresAt`/`expires_at` from the same `AGENT_DESK_NOW` the runner passed); deadline math in `http.py`.

### E.3 Startup cleanup and login ownership (R7a, R10, R11, D3)
Startup order: load+validate state → if invalid: snapshot `error: "state-unreadable"`, no cleanup, no deletions, accounts empty. Else: (a) for each isolated account: try lock (non-blocking); held → skip; else run E.2 step 3 only (refresh temp recovery with the base-hash check) and unlink any leftover `tempFiles.transaction` and `<name>.agent-desk-txn` account-state temps — transaction temps are never committed by recovery, only removed, so a later Replace's `O_EXCL` create cannot fail forever (R28); (b) list `homes/<provider>/` once (`os.scandir`, `lstat` each entry: directories only, symlinks skipped; no `realpath` comparison, so a symlinked ancestor such as a dotfiles-managed `~/.config` is fine), delete any tree not saved (`shutil.rmtree` after taking its lock non-blocking; held → skip; a tree holding `.agent-desk-login.json` whose pid+starttime still match `/proc` → rename to the quarantine name instead); a name matching `*.quarantined-*` is deleted when its recorded pid is gone and left exactly as is while the pid is live — never re-quarantined — and this reap repeats on every cycle's install-detection pass, not only at startup; (c) install detection and imports (rerun as soon as the first probe result lands, E.1); (d) schedule.
Login: `add-account` creates `homes/<p>/<uuid>` 0700 → seeds account-state entries (strip keys) → links shared entries → spawns `["omarchy-launch-terminal", sys.executable, "<plugin>/bin/agent-desk-login", "--binary", "<abs real binary from E.6>", "<provider>", "<staging>"]` via `Popen` with the runner's own environment (`uwsm-app` needs `XDG_RUNTIME_DIR` and `HYPRLAND_INSTANCE_SIGNATURE`; `minimal_env` is for collector and logout children only). The launcher is spawned by bare name on the runner's PATH, which is how tests inject a fake `omarchy-launch-terminal` (its directory prepended to the runner's PATH, G). `omarchy-launch-terminal` is `exec setsid uwsm-app -- xdg-terminal-exec --dir=… "$@"` (`/usr/share/omarchy/bin/omarchy-launch-terminal:6`); `uwsm-app` evaluates the command locally (`/usr/bin/uwsm-app:199`) and starts it as a systemd scope, so the environment does cross to the terminal — but it is the runner's environment, i.e. quickshell's, whose PATH lacks every rc-prepended directory (E.6); therefore the home variable and the binary path still travel as arguments (variable name and paths only, no tokens, R28) and `agent-desk-login` `execv`s the absolute binary, never relying on that PATH. The configured terminal comes from `~/.config/xdg-terminals.list` (ghostty here); acrogenesis `Service.qml:242` uses the same launcher. `agent-desk-login` loads `commands.login` and `homeEnv` from `<plugin>/providers/<provider>/descriptor.json` (located relative to its own path, `os.path.dirname(os.path.realpath(__file__))/../providers/…`), writes `{pid: os.getpid(), starttime: field 22 of /proc/self/stat}` to `<staging>/.agent-desk-login.json`, sets `os.environ[homeEnv] = staging`, then `os.execv(binary, [binary, *login[1:]])` — exec keeps pid and starttime, so the recorded pid *is* the CLI; its group is read live at cancel time, never recorded. No `setsid`: Ghostty already makes the command it runs the session leader (verified: its child shell has pid == pgid == sid), so `os.setsid()` would raise `PermissionError` there, and where it succeeded it would detach the CLI from its controlling tty. The runner polls as a worker job of its own type (`login-poll`, whose result only updates `login.phase`), single-flight per staging tree, each poll scheduled 1 s (`Clock`) after the previous one returns: `collector.py --mode identity --home <staging> --home-kind isolated` through the same subprocess contract as every other run (no in-process import, so an A2 fake provider works and a buggy collector cannot wedge the loop) → usable email = success; `login.phase` walks `pending-pid` (no pid file yet, at most 20 s of `Clock`, then `failed`) → `waiting` (pid file present, process live) → one of: **Add with a unique usable identity** — the same handler saves the account (`id = stagingId`, `name = email`, `kind: isolated`, active if it is the provider's first), unlinks the pid file, sets `login` to null, schedules a `force` refresh, and publishes all of that in one snapshot (no `discard_staging`, R10); **Sign in again matching this account** — phase `committing`: `replace_current_entry(this home, staging, …)` as a worker job, `expected_hash` taken under the target lock inside that job, then `discard_staging`, `login` null, `force` refresh, one snapshot (R11); `decision-replace` (matches another saved isolated account: the login-poll worker that found the match first calls `credential_hash(target)` with the E.5 lock timeout and keeps the hash beside the pending login, never on the main loop), `decision-imported` (matches the imported account: abort path), `decision-other` (Sign in again that met a different identity), or `failed`; a new `add-account`/`sign-in-again` while `login` is non-null is refused with a caption; `cancel-login` in any decision phase calls `discard_staging` without committing; pid file present but `/proc/<pid>` missing or starttime mismatch → failed login. One function, `accounts.discard_staging(staging)`, is the only path that removes a staging tree: run as a worker job whose result publishes the snapshot: gone ⇔ `/proc/<pid>` missing or starttime mismatch (read `/proc/<pid>/stat`, split on its last `)` — `comm` may contain spaces and parentheses — then `fields = rest.split()`: `fields[2]` is pgrp (original field 5), `fields[19]` is starttime (original field 22)); if live and `live_pgrp == pid` (the CLI leads its group, as under Ghostty), `os.killpg(live_pgrp, SIGTERM)`, wait ≤ 2 s, `killpg(live_pgrp, SIGKILL)`, wait ≤ 2 s; otherwise (a terminal that left the CLI in its own group) collect the descendant set by walking `/proc/*/stat` ppid links from `pid` until the set stops growing, then TERM and KILL exactly that set with the same waits, never `killpg` on the terminal's group; both waits go through `Clock.sleep` so FakeClock tests never sleep for real (grandchildren the CLI forked die with the group); then `rmtree`; only a pid or starttime mismatch means the process is gone and nothing is signaled; still present → rename to quarantine. Explicit Cancel, failed login, decline, discard, abort, the 20 s pending cap, and the Replace commit (E.5) all call it; **panel close does not** (spec v12.5): the shell's `KeyboardPanel` dismiss layer (API doc §2.2, `KeyboardPanel.qml:280-333`) closes the panel on the first click the login terminal or browser needs, so the runner keeps the login alive across close and the panel re-renders the card from `snapshot.login` on reopen; a runner exit leaves the tree for D3's startup pass, which quarantines it while the login is live. Never logout on staging trees (A6). Sign in again on the *imported* account (R11): no staging, no ownership, no polling — spawn `["omarchy-launch-terminal", "/usr/bin/env", "<homeEnv>=<account.home>", "<abs real binary>", *login args]` (absolute `/usr/bin/env`: the systemd-launched terminal's PATH is not the user's) when the imported account's `homeFromEnv` is true (`xdg-terminal-exec` runs the command directly — no interactive shell, no rc files — and the environment it inherits is quickshell's, which lacks every rc-set variable, so without the explicit assignment the CLI would write the stock default home), and `["omarchy-launch-terminal", "<abs real binary>", *login args]` with no override when it is false (setting the variable would move Claude's `.claude.json`), show the caption "Signing in with `claude auth login` in the terminal · refresh when done"; the next manual refresh picks the result up. A successfully saved add gets a Scheduler entry due now with `force` (E.1) so its card fills on the next loop turn. Identity match (§4 normalization in `record.py::normalize_email`) decides the outcome per R10/R11 and is emitted as `login.phase`; the QML shows the decision card and answers with `login-decision`.

### E.4 Isolated-home validation (R8, D4) — `paths.isolated_home(provider, account_id, *, need=())`
`account_id` matches `^[0-9a-f]{32}$`, provider `^[a-z0-9-]+$`; `path = homes/provider/id` (lexical join, no normalization); `lstat(path)` is a directory and not a symlink, `basename == id`, `dirname == homes/provider` lexically (D4 requires the home itself to be a non-symlink direct child; ancestors may be symlinks, so no `realpath` equality), owned by `os.getuid()`, mode `0o700` (else fail closed: `PathError` → snapshot `caption`, operation aborted); for each name in `need` (credential, account-state, temp files) `lstat` is absent or a regular non-symlink file. Shared-entry health (`shared.health(home, descriptor, recorded_default_home)`): per entry `ok|missing|diverged` (`diverged` = exists but `os.readlink` ≠ `<recorded default home>/<entry>`, or is not a symlink). Relink: `os.rename(entry, f"{entry}.diverged.{UTC}")` with `-2`, `-3` suffixes on collision, then `os.symlink(<absolute recorded default home>/<entry>, <home>/<entry>)`; every link, at seeding or relink, uses that absolute recorded target string (A13 asserts `os.readlink` equals it). Missing entries are re-created before every Agent Desk launch (`accounts.launch`), only when the source exists. Health is computed at two points only: in `runner.merge_record` after a successful record for an isolated account, and in `accounts.launch` after relinking; both store it as `records[id].sharedHealth` (C.4), which drill-in renders (R8).

### E.5 Replacement transaction (R10, R11, D5) — `credfile.replace_current_entry(target_home, staging_home, descriptor, expected_hash)`
The commit runs as a worker job (E.1; its result publishes the snapshot), never on the main loop, because the target lock may be held by a collector for up to `collectorTimeoutSec`. The login-poll worker that discovers a `decision-replace` match calls `credfile.credential_hash(target)` (the only non-transaction read the runner makes of a credential file: per-home lock with the same timeout as below, `O_NOFOLLOW`, sha256 out, bytes discarded) before its result sets the phase, and the hash is kept beside the pending login; the commit receives it as `expected_hash`. The Sign-in-again auto-commit (E.3 `committing`) has no decision step: it takes the hash under the lock inside the same job and uses it the same way. From the moment a login enters `decision-replace` or `committing` until it exits, the target account is `held` in the Scheduler (E.1) so no collector run of ours can change the file under the pending hash. Lock order: target lock, then staging lock, each taken `LOCK_NB` and polled every 100 ms via `Clock.sleep` for at most `collectorTimeoutSec` (a collector may hold the target lock that long), then abort with the busy caption below and `discard_staging`; `credential_hash` in the login-poll worker waits the same way; then, under both locks, unlink any leftover `tempFiles.transaction` and `<name>.agent-desk-txn` files (never renamed onto the target) so the `O_EXCL` creates below cannot fail on a crash residue; then the descriptor's pidfile check as in E.2 step 2 — a live pid there aborts with caption "<name> is busy · sign in again" and `discard_staging` (the same exit as the hash mismatch below). Read target under the lock and hash it — must equal `expected_hash`, else abort with caption "<name> changed while you decided · sign in again" and `discard_staging` (this is what catches a CLI write between the panel decision and the commit). Build the new document with the collector's `select` callback (E.2) applied to both files: `(tkey, _) = select(target_doc)`, `(skey, sentry) = select(staging_doc)`; new document = target document with `skey → sentry` inserted and `tkey` removed when `tkey != skey` (Grok's `issuer::principal` keys differ per login; Claude's fixed `claudeAiOauth` key makes this a plain replacement), every other entry preserved; write to `<tempFiles.transaction>` (`O_EXCL`, 0600), fsync; merge account-state: for each entry, target document with `stripKeys` taken from staging, written to `<name>.agent-desk-txn` 0600 + fsync; `os.replace` credential then account-state files (two renames: a crash between them leaves new credentials beside old identity keys; the next Sign in again repairs it, and the README says so); on any failure before the first replace, unlink temps and leave the target untouched; after a successful commit, `accounts.discard_staging(staging)` (E.3), advance the target account's `generation`, delete its record, publish state, then one `force` refresh of that account (E.1: ignores the floor and backoff, due now; R10). "Newer token" rule (A6b): `expected_hash` is the guard — any write to the target after the decision was shown aborts the commit and the target is untouched.
Removal (R11): a worker job (E.1) first marks the account `held` and takes its `.agent-desk.lock` with the bounded E.5 wait (a collector may hold it; timeout → caption "<name> is busy · try again", nothing removed, and `held` is cleared so the account stays scheduled), then runs `[<abs unmarked binary from E.6>, *logout[1:]]` in that home when `commands.logout` is non-null (null → straight to the state publish) with the collector timeout (Popen, own session, 30 s, home env var set on that child only); when the job returns the main loop publishes state without the account and, only when `active[p]` was the removed id, with `active[p] = imported id` (otherwise `active[p]` is unchanged; spec v12.4 R11, A12) → `rmtree(paths.isolated_home(provider, id))` → unlink record → snapshot. Logout exit ≠ 0 → `caption "Codex logout failed · work still removed"`. Launch (R13a): `["omarchy-launch-terminal", "/usr/bin/env", "<HOME_VAR>=<home>", "<abs real binary>", *launch args]` for isolated accounts and for an imported account with `homeFromEnv` true; an imported account with `homeFromEnv` false launches `["omarchy-launch-terminal", "<abs real binary>", *launch args]` with no override (spec v12.3 R13: the CLI's default *is* that home, and setting the variable would relocate Claude's `.claude.json`); relink (E.4) first; the variable name and paths are the only arguments (R28).

### E.6 Real-binary rule and interactive PATH (R7, R13, D6)
The shell's own PATH differs from an interactive shell's (verified on the running quickshell process: it carries `~/.local/share/mise/shims` and `~/.local/bin` but not `~/.grok/bin` or any other rc-prepended dir, so `grok` resolves differently there than in a terminal), and R13 defines "installed" against a new interactive login shell, so the runner probes `[os.environ.get("SHELL","/bin/bash"), "-lic",` (`SHELL` comes from the runner's inherited environment, which is how tests substitute `fake_shell`, G) 'printf "\\n__AGENT_DESK__%s__AGENT_DESK__\\n" "$PATH" "$CLAUDE_CONFIG_DIR" "$CODEX_HOME" "$GROK_HOME"']` through the same `Popen(start_new_session=True)` + `killpg` wrapper as collectors with `probeTimeoutSec` (default 5) so a hung rc file's children die too — one sentinel-wrapped line per value (rc files print banners such as fastfetch to stdout, so the parser takes only text between the sentinels; the variable list is built from every descriptor's `homeEnv`, in descriptor-id order after `PATH`, and the values feed the R8 import-time expansion so the default home comes from the interactive environment) **only at runner startup and on a manual refresh** (`refresh` with `manual: true`, i.e. right click, `r`, IPC, panel open), as a worker job like any other: the cached PATH keeps being served meanwhile and no snapshot ever waits on the probe; before the first result `pathProbe` is `"pending"` (treated like `"fallback"` for imports; the not-installed hint reads "Checking PATH…", never "timed out") and the fallback PATH serves that first cycle. Scheduled cycles reuse the cache. On timeout or a non-zero exit the fallback PATH is the runner's own `PATH` plus `~/.local/bin` plus every descriptor's `installDirs` (C.1), and the snapshot carries `pathProbe: "fallback"` so the panel's not-installed hint can say "PATH probe timed out". `routing.real_binary(name, path)` walks entries in order, skipping a file whose first 512 bytes contain the marker `# agent-desk routing shim v1`; first executable regular file wins; none → `not-installed` (A12a). The same PATH is given to collectors and to `--binary`. Routing verification (E.7) always runs its own `$SHELL -lic` path probe; it never uses the cache. Note: `$SHELL -lic '<cmd>'` runs no precmd hook, so mise's `hook-env` never runs inside a probe; the probe and a real prompt still agree on PATH order because `activate_aggressive` is `false` (E.7), which M4 confirms live.

### E.7 Routing shim and PATH precedence (R13, R30, D6)
Decision: install prepends `~/.local/bin` by appending a marked block to the interactive rc of `$SHELL` (`~/.zshrc` for zsh, `~/.bashrc` for bash; any other shell refuses install with a message). Rationale: on this machine mise is activated by legendary-zsh `shell/inits` via `/etc/zsh/zprofile`, before `~/.zshrc` runs, and `~/.zshrc:48` then prepends `~/.grok/bin`; the verified interactive PATH shows `~/.grok/bin` at #1, mise installs at #10–17, and `~/.local/bin` at #28, so an rc-tail prepend demonstrably wins; mise `settings activate_aggressive` is `false` (verified), so mise does not move its tool dirs ahead of later prepends; a mise `conf.d` fragment cannot win (design note D6) and relocating the shim would leave `~/.local/bin` (R30). Block bytes, appended verbatim and removed as the exact same byte sequence (A5 byte-identical):
```
\n# >>> agent-desk routing (do not edit; removed by Agent Desk) >>>\nexport PATH="$HOME/.local/bin:$PATH"\n# <<< agent-desk routing <<<\n
```
Spec v12.3 R13 / D6: the shim and every Agent Desk launch set the home variable for an imported account only when `homeFromEnv` is true. Install is refused with a caption when no launch provider is installed or while `pathProbe != "ok"`, and when `$SHELL` is neither zsh nor bash (the header line and README say so: "Routing needs zsh or bash"). Install (all-or-nothing): preflight every target `~/.local/bin/<binary>` for each installed launch provider: exists without marker → refuse whole install, write nothing (also when the conflict is on the second target); rc file exists and contains an unmarked line mentioning `agent-desk routing` → refuse; the exact block bytes already present → the rc step is a no-op (never a second block); rc file missing → it is created (0644) holding only the block. Then write each shim to `.<binary>.agent-desk.tmp` 0755 + rename; append the block to `realpath(rc)` (the rc may be a symlink: write the temp beside the real file, preserve its mode, rename there); record `routing.rcCreated` when install created the file; any failure → remove what this install wrote. Verify per provider with a path-only lookup (`command -v` would return alias or function text): `$SHELL -lic 'whence -p <binary>'` for zsh, `type -P <binary>` for bash, sentinel-wrapped as in E.6; the value must equal `~/.local/bin/<binary>`; else `shadowed[<provider>] = dirname(resolved)`, or the literal `"an alias or function"` when the shell also reports one via `whence -w`/`type -t` (reported as "shadowed by an alias or function"), and `routing.partial = true`; a partial install still records `installed: true`, so the header offers Remove, never Install again. Removal: delete marked shims, remove the exact block bytes from `realpath(rc)` the same way (temp beside the real file, mode preserved, rename); an rc file that install created (`rcCreated`) and that is empty afterward is deleted; a block whose start marker is present but whose bytes no longer match (edited by hand) is left in place and reported, as are unmarked files. Marker check = file is a regular non-symlink and contains the marker line. While routing is on, each runner cycle writes only the missing marked shim of a newly installed provider and never touches the rc file (R13).
Shim (`routing/shim.sh`, installed as `~/.local/bin/<binary>`; `PROVIDER`, `BINARY`, `HOME_VAR` are substituted at install; needs only bash, jq, coreutils):
```bash
#!/bin/bash
# agent-desk routing shim v1  <- marker line; never edit
set -u; provider=PROVIDER; binary=BINARY; home_var=HOME_VAR; marker='# agent-desk routing shim v1'
self_dir=$(cd -- "$(dirname -- "$(readlink -f -- "$0")")" && pwd)
real=""; IFS=: read -ra dirs <<<"$PATH"                          # drops a trailing empty entry (harmless)
for d in "${dirs[@]}"; do [[ -n $d ]] || d=.; c="$d/$binary"
  [[ -f $c && -x $c ]] || continue; [[ "$(cd -- "$d" && pwd -P)" == "$self_dir" ]] && continue
  head -c 512 -- "$c" 2>/dev/null | grep -Fq -- "$marker" && continue; real=$c; break; done
[[ -n $real ]] || { echo "agent-desk: no real $binary found on PATH" >&2; exit 127; }
[[ -v "$home_var" ]] && exec "$real" "$@"                          # explicitly set, even empty, wins (R13)
home_dir=${HOME:-}; [[ -n $home_dir ]] || exec "$real" "$@"                # unset HOME must not be a third fail-closed case (R13); set -u would exit 1
state="$home_dir/.config/omarchy/agent-desk/state.json"; homes="$home_dir/.config/omarchy/agent-desk/homes/$provider"   # C.5: pinned, XDG_* ignored on purpose
sel=$(jq -er --arg p "$provider" '.active[$p] as $id | .accounts[] | select(.provider==$p and .id==$id) | [.kind,.id,(.home // "-"),(if .homeFromEnv then "1" else "0" end)] | @tsv' "$state" 2>/dev/null) || exec "$real" "$@"
IFS=$'\t' read -r kind id home from_env <<<"$sel"; [[ $home == - ]] && home=""   # placeholders keep four fields: bash collapses consecutive tabs
if [[ $kind == imported ]]; then
  [[ $home == /* && "/$home/" != */./* && "/$home/" != */../* ]] || exec "$real" "$@"   # absolute, no . or .. component (wrapping in / catches a final segment)
  [[ $from_env == 1 ]] || exec "$real" "$@"                              # spec v12.3 R13: default home not selected by the variable at import → real CLI unchanged
  want=$home
elif [[ $kind == isolated && $id =~ ^[0-9a-f]{32}$ ]]; then
  want="$homes/$id"
  [[ ! -L $want && -d $want ]] || { echo "agent-desk: home for active $provider account is missing; open Agent Desk" >&2; exit 78; }   # isolated: real directory or fail closed (D4, R13)
else exec "$real" "$@"; fi
canon_state=$(realpath -e -- "$home" 2>/dev/null); canon_want=$(realpath -e -- "$want" 2>/dev/null)
if [[ -z $canon_want || ! -d $canon_want ]]; then
  [[ $kind == isolated ]] && { echo "agent-desk: home for active $provider account is missing; open Agent Desk" >&2; exit 78; }   # isolated realpath failure is fail-closed too
  exec "$real" "$@"; fi                                                  # imported home missing → real CLI unchanged (spec v12.2)
[[ $kind == isolated || ( -n $canon_state && $canon_state == "$canon_want" ) ]] || exec "$real" "$@"   # any other path: unchanged
export "$home_var=$want"; exec "$real" "$@"                          # the recorded path (imported) or $homes/$id (isolated), same string a launch passes (E.5)
```
Fail-closed exits are exactly the two in R13 v12.2 (127 no real binary, 78 the saved *isolated* account's home missing; a missing imported home is not fail-closed). Tokens never touch env or argv. The shim reads nothing but `state.json`. A5's "a symlink that resolves elsewhere → real CLI unchanged" binds only the imported `home` string (the only path the shim takes from state); isolated paths are derived from ids, so a symlink there is "not a real directory Agent Desk created" and exits 78 (Phase 8 keeps both tests).

### E.8 Network policy (R29, D8) — `http.py`
`http.py` reads no environment. `post`/`get` take an optional `cafile` parameter (the collector passes it only under `--test`, C.2); the module builds `ssl.create_default_context()` and, when `cafile` is given, calls `load_verify_locations(cafile=…)` on that context only; verification is never disabled and nothing process-wide changes; `urllib.request.build_opener(NoRedirect())` where `NoRedirect.redirect_request` raises `RedirectRefused` → status `failed`, no second connection; `timeout` from the deadline budget; `HTTPError` 429 → `rate-limited`, 401/403 → auth rejection, 5xx → `failed`; `URLError` with `gaierror`/`ECONNREFUSED`/`ENETUNREACH` → `offline`; `socket.timeout` → `failed`; JSON decode error → `failed`. URL must start with `https://` (asserted again here). Proxy env is ignored (`opener` built without `ProxyHandler`).

This keeps the whole model testable without the kit (G). Drill-in: `listLayer` animates `Rotation{axis y; angle 0→8}`, `Translate{x 0→-Style.space(24)}`, `opacity 1→0` and `DetailView.opacity 0→1`, all `140 ms Easing.OutCubic`; reverse on Escape/Back. `DetailView`: caption "Back" row, hero line (name, email, org, plan), rails at full width with exact reset times, detail grid (replicate the network panel's inline `InfoLabel`/value components — they are `component` declarations inside `network/Panel.qml:1925-1959`, not `qs.Ui` types) for home path, status + reason + help, last fetched, shared-entry health rows with `Button "Relink"` per diverged/missing entry.

Markup guard (R31, A14): kit text components leave `textFormat` at `AutoText` (no `textFormat` in `Ui/*.qml`), and Qt's `mightBeRichText` flips to rich text when a string starts with a tag such as `<img src=…>`; so `Format.plain(s)` inserts U+200B after every `<` and `&` and is required on every non-literal string handed to a kit `text`, `tooltipText`, `label`, `description`, or message prop (Button, PanelActionButton, Toggle, PanelToolTip, PanelSectionHeader, TextField placeholder); our own `Text` items set `textFormat: Text.PlainText` and need no guard. Caption latch (R11, R12, R19): a `caption` event replaces the live caption line and is held in QML until `opened` becomes false; later snapshots update everything else but never restore the live line while the latch holds. Panel close during a login sends nothing (spec v12.5): the login lives in the runner; on reopen the section re-renders the in-progress or decision card from `snapshot.login`, and only the card's Cancel or a decision button ends it. Runner state: `snapshot.error === "runner-stopped"` renders a status card "Runner stopped · see runner.log" above the sections, and `"runner-locked"` renders "Another runner holds runner.lock" (E.1a); manual refresh retries (E.1a). Vertical bar: `bar.vertical` hides the text and colours the icon only.
Settings: read via `setting()` in `validatedSettings` (C.6) and pushed to `desk` on change (`onSettingsChanged`); nothing is written back (no persist helper; YAGNI). Routing state lives in `state.routing`, not settings.
Runner link (`Service.qml`): `Process { command: ["python3", pluginDir + "/bin/agent-desk-runner", "serve"]; stdinEnabled: true; running: true; stdout: SplitParser { onRead: desk.handleLine(data) } ; onExited: desk.scheduleRestart() }` (`stdinEnabled`/`write` verified in `quickshell-io.qmltypes:131-135,188`); `scheduleRestart` backs off 1 s → 30 s and stops after 5 exits in 60 s with `snapshot.error = "runner-stopped"`; a manual refresh then resets the counter and sets `proc.running = true` (E.1a); on every `Process` start Service.qml sends `settings` first, then `snapshot`; `send(obj)` = `proc.write(JSON.stringify(obj) + "\n")`. `pluginDir` = `Quickshell.env("HOME") + "/.config/omarchy/plugins/" + manifestIdDir` resolved from `Qt.resolvedUrl(".")` once. Refresh triggers → `refresh{…, manual:true}` (always explicit, C.4): panel open (`onOpenedChanged`), `r`, right click, IPC, and the past-reset queue, whose single owner is `Keys.State`: on every panel open and every 30 s tick Panel.qml calls `Keys.State.pastResetActions(snapshot, nowMs)` and sends the returned `refresh{accountId}` actions (R21: per window id + reset timestamp, one per key; `tst_keys.qml` covers it). Nothing on disk is watched by QML: the runner is the single writer and pushes a full snapshot after every change, which avoids the stale `FileView.text()` hop and duplicate truth.

## G. Test strategy (R34, A1–A14)

TDD order per phase: write the named test files first (they fail on import or assertion), implement, then refactor. Python: stdlib `unittest`, run `python3 -m unittest discover -s tests -v` (no third-party packages; base system only, R32). Fixtures: `tests/fixtures/homes/<provider>/<case>/` (signed-in, expired-9min, expired-10min, api-key-only, not-signed-in, two-entries) copied into a `tempfile.TemporaryDirectory` per test by `tests/support/homes.py`, which also fabricates a fake default home, `HOME`, both data dirs, and — for every runner-level test — sets `SHELL` to `tests/support/fake_shell`, a script that answers the E.6 probe with a PATH whose first entry is `tests/support/fake_cli/` and empty home variables, so `pathProbe` reaches `"ok"` and the fake CLIs and launcher are what the runner resolves. A fake `omarchy-launch-terminal` (records its argv, runs the wrapper directly in the background, exits at once) is injected by prepending `tests/support/fake_cli/` to the runner's PATH (E.3). Fake CLIs (`tests/support/fake_cli/{claude,codex,grok}`, python) take their whole script from `$HOME/.fake-cli.json` (the runner strips every other env var, E.1): `{loginDelay, loginWaitsForGo, logoutExit, logLog, codexRpcFixture, ...}`; `login` waits for `<home>/go` (or the delay), then writes fixture credentials; `logout` appends to the log file and exits with the scripted code; `codex app-server` speaks the RPC from the fixture; `auth status` prints the home's email. Canned HTTP: `tests/support/fixture_server.py` — `http.server` + `ssl` on 127.0.0.1 with the checked-in test cert (`AGENT_DESK_CA_FILE` set on a runner started with `serve --test`, which is the only way it reaches a collector and `http.py`'s `cafile` parameter, C.2/E.8; no ambient passthrough exists), routes `{(method,path): (status, headers, body, delay)}`, records every request (headers, body) for the A8 scan and the "no second request" assertions; test descriptors are copies of the real ones with `urls` pointing at the server (still `https://`). In-process unit tests inject `http=` and `clock=` directly. Clock: `FakeClock` for runner, credfile, collectors; the login poll and timeouts use `Clock.sleep`, which a fake advances instantly. Process-group and 30 s tests run the real runner with a fake collector that sleeps and forks a grandchild, with `collectorTimeoutSec`, `probeTimeoutSec`, and grace set to 0.2 s scaled values through the Scheduler constructor and a `FakeClock`. This is the one explicit R34 exception: `select` and `Popen.wait` are wall-clock, so process-liveness tests wait real but scaled fractions of a second (< 1 s total) and assert on liveness, never on elapsed time.
